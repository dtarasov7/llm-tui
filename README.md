# llm-tui

English | [Русский](README-ru.md)

Version **1.0.0** appears at the top of the TUI on startup. To check it without
starting the interface: `python3.8 llm-tui.py --version`.
Changelog: [English](CHANGELOG.md), [Russian](CHANGELOG-ru.md).

A terminal client for engineering work with local llama.cpp and vLLM servers.
One executable file, Python 3.8+, standard library only; on Linux, Python must
include `curses`. Code generated by the model is displayed, saved, and exported,
but never executed.

```bash
python3.8 llm-tui.py
python3.8 llm-tui.py --self-test
```

All data and logs can be stored under a directory of your choice:

```bash
python3.8 llm-tui.py --storage-dir /path/to/my-llm-tui
python3.8 llm-tui.py --storage-dir /path/to/my-llm-tui --paths
```

`--paths` shows the effective paths without creating files; use `/paths` inside
the TUI. The defaults are `./llm-tui/data` and `./llm-tui/logs`, relative to the
current working directory. Use separate roots with `--storage-dir` for different
users, including those running via sudo. The session lock prevents a second
instance from starting with the same data directory.

To hide reasoning text and show only `Thinking` with a character count:

```bash
python3.8 llm-tui.py --reasoning-view summary
```

Inside the application, run `/reasoning summary` or press **F6 / Ctrl+D**.
The current mode is always shown next to the input area: `F6 мысли: текст`
(reasoning text) or `F6 мысли: счётчик` (character count).

An interactive UTF-8 terminal is required. The recommended size is 80×20 or larger.
If the backend is unavailable, the interface still opens, and archives and exports
remain available.

## Backends and models

The editable `BACKENDS` dictionary is at the beginning of `llm-tui.py`.
It contains `llama-local` and `vllm-main` entries. Set your server address and,
optionally, a model; see `BACKENDS` or `/backend` for the current addresses.
The URL may include a reverse proxy prefix and end with `/v1`.

To add a backend, add an entry to `BACKENDS` with these fields:

```python
"my-vllm": {
    "type": "vllm",                # or "llama.cpp"
    "url": "http://localhost:8000",
    "model": None,                 # None: first model from /v1/models
    "api_key_env": "VLLM_API_KEY",
    "context_size": "auto",        # or an explicit positive integer override
    "thinking_supported": False,
},
```

A nonempty environment variable named by `api_key_env` takes precedence over
`api_key`. Keys are never written to sessions or logs. Session files may contain
sensitive text from your requests and sources; new JSON files use permissions 0600.

`DEFAULT_BACKEND` selects the initial backend for a new session. A saved session
restores its previous selection; `--backend NAME` overrides it at startup.

```text
/backend                 show configured servers
/backend vllm-main       switch backend; keep the transcript
/backend llama-local     select llama.cpp or reconnect
/model                   refresh and show the model list
/model model-name        select a model
```

Switching the backend or model stops the current generation and refreshes metadata
asynchronously. The partial answer is saved. Once the server recovers, repeat the
request with `/retry` or reconnect with `/backend NAME`.

## Input and commands

| Key | Action |
|---|---|
| Ctrl+G | Send a request or execute a command |
| Enter | Insert a newline |
| Ctrl+Enter | Send if the terminal supports CSI-u/modifyOtherKeys |
| Arrow keys, Home/End, Backspace/Delete | Edit multiline input |
| Ctrl+P / Ctrl+N | Browse input history; restore the draft after the last entry |
| Tab | Complete a command, role, backend, model, or alias |
| PgUp / PgDn | Scroll the transcript, including during streaming |
| Ctrl+W | Switch focus between the editor and answer viewer |
| Ctrl+T / Ctrl+B | Go to the beginning / end of the transcript |
| F1 / F2 / F3 / F4 / F5 | Help / roles / archives / sources / context |
| Ctrl+K / Ctrl+R / Ctrl+S / Ctrl+F / Ctrl+O | The same actions if the terminal intercepts function keys |
| F6 / Ctrl+D | Toggle reasoning display: full text / indicator |
| Ctrl+Y | Copy the selection, or the entire last answer if nothing is selected |
| f (in the answer viewer) | Save the selection, or the entire last answer, to a `.clb` file |
| Esc | Stop a network operation or generation |
| Ctrl+L | Redraw the screen |
| Ctrl+Q | Save and quit |
| Ctrl+C | Stop the current operation; otherwise quit |

Viewer shortcuts work with the Russian keyboard layout and Caps Lock, using
the same physical key positions:

| Action | English layout | Russian layout |
|---|---|---|
| Start / clear selection | v / V | м / М |
| Send selection to the clipboard | y / Y | н / Н |
| Save selection to a file | f / F | а / А |

In the editor, these letters are entered as ordinary text, preserving layout and
case. Bracketed paste does not trigger shortcuts either. F1–F6 and Ctrl control
codes work identically in both panels, including when viewing help, roles,
archives, and files.
Ctrl shortcuts also support [CSI-u/kitty](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)
and modifyOtherKeys: Russian letters, uppercase letters, and Caps/Num Lock flags.
If the terminal sends a base-layout key code, that code takes precedence.
Key release events in extended protocols do not trigger the action again.
Function keys, navigation, and Shift+arrow keys are recognized with Caps Lock too.

The application handles the data received from the terminal. If PuTTY intercepts
a shortcut or sends an ordinary letter instead of a Ctrl code, the program cannot
distinguish it from text input. Actual Windows/PuTTY operation is outside the
automated checks; tests cover received codes and sequences in both panels and
with information screens open.

Bracketed paste supports multiline text. Enter does not send a message.
After manual scrolling, streaming does not return the viewer to the bottom;
Ctrl+B resumes following new tokens.

Function keys are recognized through curses/terminfo and common SS3/CSI/Linux
sequences. After a command result or a new notification, the upper panel scrolls
to the bottom: the final line is visible even when help or `/context` output is
larger than the panel. This applies to all commands, including F1–F5 and errors;
focus stays in the current panel. Use PgUp to read the beginning of a long result;
Ctrl+W enables cursor navigation and selection. You can continue typing directly
from the editor. Sending a new request returns the upper panel to the current
conversation and follows the answer. Manual scrolling during generation disables
following again. Use **Ctrl+W** or `/select` to enter the viewer and select text.
If the terminal emulator intercepts a function key before passing it to the
application, use the corresponding Ctrl shortcut from the table.

Redrawing does not reset manual scrolling after `/context`, F1, or other commands.
Incoming answer tokens preserve the viewing position after a manual PgUp;
Ctrl+B returns to the last line and resumes following new tokens.

## Scrolling and copying answers

In the editor, PgUp/PgDn scroll the upper panel while arrow keys edit the input.
**Ctrl+W** moves focus to the transcript, where arrow keys, PgUp/PgDn, and Home/End
(beginning/end of the transcript) are available. The bottom line shows the current
mode and shortcut hints. Switching focus preserves your draft.

To copy part of an answer, including a selection larger than one screen:

1. Run `/select` to move the cursor to the beginning of the last answer.
2. Find the start of the desired fragment with the arrow keys and press **v**.
3. Move to the end with arrow keys or several **PgDn** presses. The selection is
   highlighted; paging and resizing do not clear it.
4. Press **f** to save the selection to a file, or **y** / **Ctrl+Y** to send it to
   the clipboard. Over SSH, copying requires OSC52 support in the terminal;
   sending the sequence does not confirm that copying succeeded.
5. **Enter**, **Ctrl+W**, or Esc when no generation is running return to the editor.

You can start a selection with Shift+arrow keys instead of v. Pressing v again
clears the mark. Automatic line wrapping to the terminal width does not insert
extra newlines into the copied text.

**f** works only in the viewer; it is an ordinary letter in the editor.
The file is created on the server under `<data-dir>/exports/`, with a name such as
`save-YYYYMMDD-HHMMSS-microseconds.clb`, for example
`save-20261004-153012-123456.clb`. It contains plain UTF-8 text with LF line endings.
The exact selected fragment is saved, including selections larger than a screen;
without a selection, the entire last answer is saved. The path appears in the
bottom line, and focus and selection are preserved. Existing files are never
overwritten. The same action is available from the editor through `/saveclip`.

Without making a selection, you can copy the entire last answer or a range of its
lines, regardless of the screen size:

```text
/copy
/copy 10 200
```

The default is `CLIPBOARD_METHOD="auto"`: local sessions use `wl-copy`, `xclip`, or
`xsel` if available in the appropriate graphical session. Over SSH, under sudo,
or without those utilities, the application sends
[OSC52](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) to the terminal.
The terminal and any intermediate multiplexer must allow clipboard writes;
the application cannot confirm that OSC52 was accepted. Terminals have different
transfer size limits; for very large fragments, choose a local utility or save
the answer with `/save`.

You can select the method explicitly:

```bash
python3.8 llm-tui.py --clipboard-method osc52
python3.8 llm-tui.py --clipboard-method wl-copy
```

No Python dependencies are added; clipboard utilities are optional. Failure of an
explicitly selected utility is shown in the bottom line. `/save` remains available
regardless of the terminal's clipboard support.

### PuTTY on Windows with a server without a GUI

When connecting over SSH, the clipboard is on the Windows PC. PuTTY handles
**Shift+mouse** selection: releasing the mouse button copies the text to the
Windows clipboard. This selection is separate from v/arrow selection inside the
application. See the
[official PuTTY manual](https://the.earth.li/~sgtatham/putty/0.85/htmldoc/Chapter3.html#using-copy).
Installing `xclip` or `wl-copy` on the server does not provide access to the
Windows clipboard.

Over SSH, `y`, Ctrl+Y, and `/copy` send OSC52. If PuTTY or an intermediate
multiplexer does not handle it, the Windows clipboard is unchanged. The
application reports that copying is unconfirmed rather than claiming success.

For an answer larger than the screen, save the entire answer with
`/save /absolute/path/answer.txt`, exit with `/quit`, and run
`cat /absolute/path/answer.txt` in the shell. Then select the desired fragment
with the mouse while scrolling PuTTY's history. Shift+PgUp/Shift+PgDn scroll
PuTTY's own history; PgUp/PgDn inside the application scroll the conversation.
The curses conversation does not necessarily enter terminal scrollback, so
scrollback does not replace upper-panel scrolling. If the answer exceeds PuTTY's
history, increase `Window → Lines of scrollback` or download the saved file to
your PC and open it in a text editor.

A command is recognized only when `/` is the first non-whitespace character.
`Check URL /system/test` remains an ordinary request. Arguments are parsed with
`shlex.split`, so quote paths containing spaces.

All commands accept an **unambiguous leading prefix** from the shared registry:
`/sys python` = `/system python`, `/rel code` = `/reload code`.
`/s` and `/re` are ambiguous: no action is taken, candidates are displayed, and
the original input stays in the editor. An exact name always takes precedence.
`/help` is generated from the registry and shows the shortest valid prefixes.

Main commands:

```text
/help                     commands and shortcuts
/new [name]               archive the current conversation and start a new one
/clear                    archive and clear the current session
/archive [name]           save a snapshot without clearing
/sessions                 list archives
/open ID                  restore an archive; a unique ID prefix is accepted
/system [role]            show or select a system role
/load "path with spaces" code
/reload code              reread a file; keep the old copy on failure
/files                    sources, sizes, line counts, changes on disk
/unload code              remove a source
/context                  detailed count of the current context
/status                   current status
/paths                    effective storage paths
/select                   view and select the last answer
/copy [FIRST LAST]        copy an answer, selection, or line range
/save [PATH]              export the last answer
/code                     list fenced code blocks in the last answer
/code script.py           export the only block
/code 2 playbook.yml      export the selected block
/search TEXT              case-insensitive search; repeat to find the next match
/retry                    repeat the last user request with current settings
/stop                     stop and preserve the partial answer
/reasoning [full|summary] show reasoning text or a live character count
/quit                     save and quit
```

`/save` and `/code N` without a path create a file in exports. Existing files are
never overwritten: choose another name. `/retry` keeps the previous attempt in
the transcript, marks it as superseded, and excludes it from subsequent API context.

## Sources and context

Loading a file does not send it to the model automatically:

```text
/load test.py code
Review @code
Review only @code#L10-L30
```

A single line is supported too: `@code#L50`. Line numbers start at 1, and bounds
are checked. Sources are read as UTF-8; binary files and files exceeding
`MAX_SOURCE_FILE_BYTES` are rejected.

Only explicitly referenced sources are added to the current API request, with
paths and line numbers. A snapshot of the expanded request is saved in metadata
for history, but sources are not automatically attached to later API requests.
Use `@alias` again to analyze a source again.

The context size is determined from the selected model's metadata or llama.cpp
`/props`. If a model is selected, the TUI requests
`/props?model=<URL-encoded name>`; this works both with a single model and with a
[router serving multiple models](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#routing-requests).
It uses `default_generation_settings.n_ctx`, the runtime context per slot, rather
than the training `n_ctx_train` from GGUF. The limit is detected again after
`/model NAME`. In router mode, a metadata request may automatically load the
selected model, depending on llama-server settings. The `/props` response is
awaited for up to `HTTP_TIMEOUT` (60 seconds by default); connection establishment
uses `CONNECT_TIMEOUT` (5 seconds). This work runs in a network thread and can be
cancelled with Esc. The selected model name is also passed to `/apply-template`
and `/tokenize`, so the router uses that model's template and tokenizer when
counting context. An explicit numeric `context_size` in `BACKENDS` takes precedence
over the detected value. A runtime override is saved in the session:

```text
/context max 131072
/context reserve 8192
/context auto
```

`/context auto` removes the runtime override and returns to the backend
configuration. An unknown limit is shown as `?` with a warning; automatic
trimming is disabled. No maximum is invented.

llama.cpp uses `/apply-template` + `/tokenize`; vLLM uses chat-aware `/tokenize`.
If an endpoint is missing or returns invalid data, a clearly marked estimate `~`
is used. While typing and until an exact count arrives, the status is approximate
too. F5 makes the worker count the actual editor text; `/context` counts history
without the command text itself. Breakdown components are approximate because
template overhead cannot be added independently.

`response_token_reserve` is subtracted from the budget; with an explicit
`max_tokens`, the reserve is at least that value. On overflow, the oldest turns
are removed from API context only. The complete transcript remains available.
The system prompt, current request, and its sources are never removed; if they
do not fit, the request is rejected with a budget explanation and a suggested
line range.

The reserve does not impose a generation limit on the server: in SERVER mode,
the server controls answer length. Use `/sampling max_tokens N` for an explicit
limit.

## Sampling and thinking

The default is `SERVER`: optional sampling parameters are omitted, and the
server's settings are used. Overrides apply only to parameters you specify:

```text
/sampling
/sampling temp 0.6
/sampling top_p 0.95
/sampling top_k 20
/sampling min_p 0
/sampling presence_penalty 1.5
/sampling max_tokens 8192
/sampling server
/sampling reset
```

The vLLM adapter maps `repeat_penalty` to `repetition_penalty`.
Unknown parameters, NaN, and invalid values are rejected.

`/thinking auto` leaves the model's defaults unchanged. `/thinking on` and
`/thinking off` send `chat_template_kwargs.enable_thinking` if the backend has
`thinking_supported=True`. Enable this flag only after checking that the
**current model and its template** support the switch: not every reasoning model
allows thinking to be disabled. Without the flag, the switch is rejected with a
message. Separate reasoning deltas are displayed and saved in metadata;
`/save` exports the final answer text.

**Reasoning display** is controlled separately from the model's settings:

```text
/reasoning full
/reasoning summary
```

F6 or Ctrl+D toggles these modes without stopping generation. `full` shows the
text; `summary` shows only `Thinking`, an animated indicator, the number of
received reasoning characters, and elapsed time. After the answer, a marker
shows the number of hidden characters. The bottom progress line updates even
while no new data arrives: the counter reflects only characters actually
received. Switching modes during generation displays the current answer.
The current mode is always shown above the editor: `F6 мысли: счётчик` in summary
mode and `F6 мысли: текст` in full mode. `/reasoning summary` explicitly enables
summary mode; `/reasoning full` restores the full text.

Separate API reasoning fields and a leading `<think>…</think>` block in the text
stream are supported, including tags split across chunks. Reasoning is saved in
metadata even when hidden. The selected mode is saved in the session; use
`--reasoning-view summary` to select it at startup. The initial value is set by
`DEFAULT_REASONING_VIEW` at the beginning of the file. `/thinking` changes model
parameters, while `/reasoning` changes only the display.

System prompts are defined in `SYSTEM_PROMPTS`: general, architect, security,
python, bash, linux, ansible, devops, sre, network, database, code-review,
troubleshooter, log-analyzer, and performance. Switching roles preserves the
conversation.

## Data, logs, and verification

By default, all service files are stored under `./llm-tui`, relative to the current
working directory. No graphical environment is required. XDG variables are no
longer used; the old `--state-dir` option has been replaced with `--log-dir`.

| Option | Contents and path selection |
|---|---|
| `--storage-dir ROOT` | Shared root; defaults to `./llm-tui`. Alternatively, set `LLM_TUI_HOME`. |
| `--data-dir DIR` | Sessions, archives, exports, and the lock file directly in `DIR`; defaults to `<storage-dir>/data`. |
| `--log-dir DIR` | Logs directly in `DIR`; defaults to `<storage-dir>/logs`. |

For example, `python3.8 llm-tui.py --storage-dir /srv/llm-tui/alice` uses
`/srv/llm-tui/alice/data` and `/srv/llm-tui/alice/logs`. Choose a different root for
another user. `--paths` prints the effective paths and exits immediately.
The application UI remains in Russian: `--help`, `/help`, and shortcut hints are
translated into Russian; command names and values such as `auto`, `full`, and
`summary` remain unchanged.

Default layout:

```text
./llm-tui/data/current.json
./llm-tui/data/archive/*.json
./llm-tui/data/exports/*
./llm-tui/data/session.lock
./llm-tui/logs/llm-tui.log
```

The automatic `sudo-UID` suffix is no longer added. Give each person a separate
root explicitly, or use different working directories.

For a chosen root:

```text
ROOT/data/current.json
ROOT/data/archive/
ROOT/data/exports/
ROOT/data/session.lock
ROOT/logs/llm-tui.log
```

Root selection priority: `--storage-dir` → `LLM_TUI_HOME` environment variable →
`STORAGE_DIR` at the beginning of the Python file (initially `./llm-tui`). Explicit
`--data-dir` and `--log-dir` options override the corresponding parts of this
selection.

Old sessions are not moved automatically. To use them, set `--data-dir` to the
previous data directory and `--log-dir` to the previous log directory.

There is no separate disk cache. Token counts and rendering are cached in process
memory. The data directory also contains temporary files for atomic saves and,
if a session is corrupted, `corrupt-*.json`. New data/log directories use
permissions 0700. `session.lock` prevents two instances from writing to the same
current.json simultaneously, even when they specify the same explicit path.
The lock is released on exit; the remaining lock file does not need to be deleted.

Paths can be overridden without editing the code:

```bash
python3.8 llm-tui.py --data-dir ./data --log-dir ./logs
```

Messages, sources, input history, drafts, and settings are saved.
JSON is written atomically using a temporary file, fsync, and os.replace.
A corrupted current.json is preserved as `corrupt-*.json`, and a new session is
created. Logs rotate; `DEBUG=True` or `--debug` enables diagnostics without API keys.

Checks that do not require a backend:

```bash
python3.8 -m py_compile llm-tui.py
python3.8 llm-tui.py --self-test
```

The API adapters have been checked against the
[llama.cpp documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
and the [vLLM tokenize protocol](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/serve/tokenize/protocol.py).
External endpoints may differ between versions; failures of optional tokenizer
or metadata endpoints use fallbacks, and HTTP errors appear in the transcript
and logs.
