# llm-tui

[English](README.md) | Русский

Версия **1.1.0** отображается в верхней части TUI при запуске. Проверить без
запуска интерфейса: `python3.8 llm-tui.py --version`.
История изменений: [на русском](CHANGELOG-ru.md), [на английском](CHANGELOG.md).

Изменения в 1.1.0:

- Суммарные входные и выходные токены в строке состояния; подробности через `/tokens`.
- Просмотр текста промпта через `/system show [РОЛЬ]`; выбирается одна основная
  роль, требования других направлений добавляются в текст задачи.
- Выполненные команды TUI в сохраняемой истории Ctrl+P/Ctrl+N.
- Alt+Enter или Ctrl+G для отправки; Enter вставляет новую строку. В PuTTY отключите
  **Window → Behaviour → Full screen on Alt-Enter**.

Инженерный TUI-клиент для локальных llama.cpp и vLLM. Один исполняемый файл,
Python 3.8+, только стандартная библиотека; на Linux требуется Python с `curses`.
Код модели отображается, сохраняется и экспортируется, но никогда не выполняется.

```bash
python3.8 llm-tui.py
python3.8 llm-tui.py --self-test
```

Все данные и логи можно разместить в одном выбранном каталоге:

```bash
python3.8 llm-tui.py --storage-dir /path/to/my-llm-tui
python3.8 llm-tui.py --storage-dir /path/to/my-llm-tui --paths
```

`--paths` показывает действующие пути без создания файлов; внутри TUI используйте
`/paths`. По умолчанию используются `./llm-tui/data` и `./llm-tui/logs`
относительно текущего рабочего каталога. Для разных пользователей, включая sudo,
указывайте отдельные корни через `--storage-dir`; второй экземпляр с тем же
каталогом данных не запустится из-за блокировки сессии.

Чтобы скрыть текст рассуждений и видеть только `Thinking` со счётчиком символов:

```bash
python3.8 llm-tui.py --reasoning-view summary
```

В открытом приложении выполните `/reasoning summary` или нажмите **F6 / Ctrl+D**.
Текущий режим постоянно виден у поля ввода: `F6 мысли: текст` либо `F6 мысли: счётчик`.

Нужен интерактивный терминал с UTF-8. Рекомендуемый размер — 80×20 или больше.
При недоступном backend интерфейс открывается, архивы и экспорт продолжают работать.

## Backend и модели

В начале `llm-tui.py` находится редактируемый словарь `BACKENDS`.
Настроены записи `llama-local` и `vllm-main`. Укажите адрес своего сервера
и при необходимости модель; текущие адреса смотрите в `BACKENDS` или `/backend`.
URL может содержать префикс reverse proxy и завершаться `/v1`.

Для добавления backend добавьте запись в `BACKENDS` с полями:

```python
"my-vllm": {
    "type": "vllm",                # либо "llama.cpp"
    "url": "http://localhost:8000",
    "model": None,                 # None: первая модель из /v1/models
    "api_key_env": "VLLM_API_KEY",
    "context_size": "auto",       # либо явный положительный integer override
    "thinking_supported": False,
},
```

Непустая переменная `api_key_env` имеет приоритет над `api_key`.
Ключи не записываются в сессии или логи. Файлы сессий могут содержать чувствительный
текст ваших запросов и источников; новые JSON-файлы создаются с правами 0600.

`DEFAULT_BACKEND` выбирает начальный backend новой сессии. Сохранённая сессия
восстанавливает прежний выбор; `--backend NAME` переопределяет его при запуске.

```text
/backend                 показать настроенные серверы
/backend vllm-main       переключиться; transcript сохраняется
/backend llama-local     выбрать llama.cpp или повторно подключиться
/model                   обновить и показать список моделей
/model model-name        выбрать модель
```

Смена backend/model останавливает текущую генерацию и обновляет метаданные
асинхронно. Незавершённый ответ сохраняется. После восстановления сервера
можно повторить запрос через `/retry` или переподключиться через `/backend NAME`.

## Ввод и команды

| Клавиша | Действие |
|---|---|
| Ctrl+G | Отправить запрос или выполнить команду |
| Enter | Новая строка |
| Alt+Enter | Отправить запрос или выполнить команду; в PuTTY отключите полноэкранный режим по Alt+Enter |
| Стрелки, Home/End, Backspace/Delete | Редактировать многострочный ввод |
| Ctrl+P / Ctrl+N | История запросов и выполненных команд TUI; после последнего элемента возвращается черновик |
| Tab | Дополнить команду, роль, backend, модель или alias |
| PgUp / PgDn | Прокрутить transcript, в том числе во время streaming |
| Ctrl+W | Переключить фокус между редактором и просмотром ответа |
| Ctrl+T / Ctrl+B | Начало / конец transcript |
| F1 / F2 / F3 / F4 / F5 | Help / роли / архивы / источники / контекст |
| Ctrl+K / Ctrl+R / Ctrl+S / Ctrl+F / Ctrl+O | Те же действия, если F-клавиши перехватывает терминал |
| F6 / Ctrl+D | Переключить показ рассуждений: полный текст / индикатор |
| Ctrl+Y | Скопировать выделение, а без выделения — последний ответ целиком |
| f (в просмотре ответа) | Сохранить выделение, а без него — весь последний ответ в файл `.clb` |
| Esc | Остановить сетевую операцию или генерацию |
| Ctrl+L | Перерисовать экран |
| Ctrl+Q | Сохранить и выйти |
| Ctrl+C | Остановить текущую операцию; без неё — выйти |

Клавиши просмотра работают в русской раскладке и с Caps Lock по тому же
расположению на клавиатуре:

| Действие | Английская раскладка | Русская раскладка |
|---|---|---|
| Отметить / снять выделение | v / V | м / М |
| Передать выделение в буфер | y / Y | н / Н |
| Сохранить выделение в файл | f / F | а / А |

В редакторе эти буквы вводятся как обычный текст, без изменения раскладки
или регистра. Вставка bracketed paste также не запускает горячие клавиши.
F1–F6 и управляющие коды Ctrl обрабатываются одинаково в обеих панелях,
включая просмотр справки, ролей, архивов и файлов.
Для Ctrl поддерживаются также [CSI-u/kitty](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)
и modifyOtherKeys: русские буквы, заглавные буквы и флаги Caps/Num Lock.
Если терминал передаёт код клавиши базовой раскладки, он имеет приоритет.
Отпускание клавиши в расширенном протоколе не выполняет действие повторно.
F-клавиши, навигация и Shift+стрелки распознаются и при флаге Caps Lock.

Приложение обрабатывает данные, полученные от терминала. Если PuTTY
перехватывает комбинацию или отправляет обычную букву вместо Ctrl-кода,
программа не может отличить её от ввода текста. Реальный Windows/PuTTY
не входит в автоматические проверки; тесты проверяют поступающие коды и
последовательности в обеих панелях и при открытых информационных экранах.

Bracketed paste позволяет вставлять многострочный текст. Обычный Enter не
отправляет сообщение. При ручной прокрутке streaming не возвращает просмотр вниз;
Ctrl+B включает следование новым токенам.

Alt+Enter выполняет команду из редактора или отправляет запрос, как Ctrl+G.
TUI включает различение клавиш в терминалах с протоколом kitty/CSI-u и восстанавливает
предыдущий режим при выходе. Также распознаются последовательности modifyOtherKeys.
Для обычных терминалов поддерживается Escape перед Enter. Обычный Enter в
редакторе сохраняет поведение вставки новой строки.

В PuTTY отключите **Window → Behaviour → Full screen on Alt-Enter**, чтобы
комбинация передавалась приложению. Во время соединения эти настройки доступны
через меню окна → **Change Settings**. Сохраните настройку в своей сессии PuTTY.
См. [официальную документацию](https://the.earth.li/~sgtatham/putty/0.85/htmldoc/Chapter4.html#config-altenter).

Команды, введённые в редакторе и успешно выполненные, включая сокращения вроде
`/sys ansible`, сохраняются в истории вместе с запросами. Ctrl+P возвращает
предыдущую запись, Ctrl+N — следующую и затем черновик. История сохраняется
в сессии; горячие клавиши просмотра справки и других панелей её не заполняют.

F-клавиши распознаются как через curses/terminfo, так и по распространённым
SS3/CSI/Linux-последовательностям. После вывода команды или нового уведомления
верхняя панель прокручивается вниз: последняя строка результата видна, даже если
вывод справки или `/context` больше панели. Это правило действует для всех команд,
включая F1–F5 и ошибки; фокус остаётся в текущей панели. У длинного результата
можно прочитать начало через PgUp; Ctrl+W включает перемещение курсора и выделение.
Из редактора можно сразу продолжать ввод. После отправки нового запроса верхняя
панель возвращается к текущему диалогу и следует за ответом. Ручная прокрутка
во время генерации снова отключает это следование. Для перехода к просмотру
и выделению используйте **Ctrl+W** или `/select`. Если эмулятор перехватывает F-клавишу
до передачи приложению, используйте соответствующую Ctrl-комбинацию из таблицы.

Отрисовка не сбрасывает ручную прокрутку после `/context`, F1 или других команд.
Поступающие токены ответа сохраняют положение просмотра после ручного PgUp;
Ctrl+B возвращает к последней строке и включает следование новым токенам.

## Прокрутка и копирование ответа

В редакторе PgUp/PgDn прокручивают верхнее окно, а стрелки редактируют ввод.
**Ctrl+W** переводит фокус в transcript: там работают стрелки, PgUp/PgDn и Home/End
(начало/конец transcript). Текущий режим и подсказки видны в нижней строке.
Набранный запрос сохраняется при переключении фокуса.

Чтобы скопировать часть ответа, в том числе больше одного экрана:

1. Выполните `/select` — курсор перейдёт к началу последнего ответа.
2. Стрелками найдите начало нужного фрагмента и нажмите **v**.
3. Дойдите до конца фрагмента стрелками или несколькими **PgDn**. Выделение
   подсвечивается; переход между страницами и resize не сбрасывают его.
4. Нажмите **f**, чтобы сохранить выделение в файл, либо **y** / **Ctrl+Y**,
   чтобы передать его в буфер обмена. Через SSH копирование требует поддержки
   OSC52 в терминале; отправка не подтверждает копирование.
5. **Enter**, **Ctrl+W** или Esc без генерации возвращают в редактор.

Вместо v можно начать выделение через Shift+стрелки. Повторное v снимает отметку.
Автоматические переносы по ширине терминала не добавляют переводов строк в буфер.

**f** работает только в режиме просмотра; в редакторе это обычная буква.
Файл создаётся на сервере в `<data-dir>/exports/` с именем
`save-ГГГГММДД-ЧЧММСС-микросекунды.clb`, например
`save-20261004-153012-123456.clb`. Внутри — обычный текст UTF-8 с переводами строк LF.
Сохраняется именно выделенный фрагмент, включая часть больше экрана; без
выделения — весь последний ответ. Путь показывается в нижней строке, фокус
и выделение сохраняются. Существующие файлы не перезаписываются.
Из редактора то же действие доступно командой `/saveclip`.

Без ручного выделения можно скопировать весь последний ответ или диапазон его
строк; длина ответа относительно экрана не имеет значения:

```text
/copy
/copy 10 200
```

По умолчанию `CLIPBOARD_METHOD="auto"`: локально используются `wl-copy`, `xclip`
или `xsel`, если они доступны в соответствующей графической сессии. Через SSH,
при sudo или без утилит приложение посылает
[OSC52](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) в терминал.
Терминал и промежуточный мультиплексор должны разрешать запись в clipboard;
приложение не может подтвердить принятие OSC52. У разных терминалов есть ограничения
размера такой передачи; для очень больших фрагментов можно выбрать локальную утилиту
или сохранить ответ через `/save`.

Способ можно указать явно:

```bash
python3.8 llm-tui.py --clipboard-method osc52
python3.8 llm-tui.py --clipboard-method wl-copy
```

Python-зависимостей не добавлено; clipboard-утилиты необязательны. Неудача явно
выбранной утилиты показывается в нижней строке. `/save` остаётся доступен независимо
от clipboard терминала.

### PuTTY на Windows, сервер без GUI

При подключении через SSH буфер обмена находится на Windows-ПК. Выделение
**Shift+мышь** обрабатывает PuTTY: при отпускании кнопки текст попадает в буфер
Windows. Это отдельное выделение от `v`/стрелок внутри приложения. Подробности —
в [официальной справке PuTTY](https://the.earth.li/~sgtatham/putty/0.85/htmldoc/Chapter3.html#using-copy).
Установка `xclip` или `wl-copy` на сервер не даёт доступа к буферу Windows.

`y`, Ctrl+Y и `/copy` через SSH отправляют OSC52. Если PuTTY или промежуточный
мультиплексор его не обрабатывает, буфер Windows не меняется. Приложение сообщает
«копирование не подтверждено», а не успешное копирование.

Для ответа больше экрана можно сохранить весь ответ командой
`/save /полный/путь/ответ.txt`, выйти через `/quit` и в оболочке выполнить
`cat /полный/путь/ответ.txt`. Затем выделить нужный фрагмент мышью с прокруткой
истории PuTTY. Shift+PgUp/Shift+PgDn прокручивают историю самого PuTTY;
PgUp/PgDn внутри приложения прокручивают диалог. Диалог curses не обязательно
попадает в историю терминала, поэтому она не заменяет прокрутку верхней панели.
Если ответ превышает историю PuTTY, увеличьте `Window → Lines of scrollback`
или скачайте сохранённый файл на ПК и откройте в текстовом редакторе.

Команда распознаётся только по первому непробельному символу `/`.
`Проверь URL /system/test` остаётся обычным запросом. Аргументы разбираются
`shlex.split`, поэтому пути с пробелами заключайте в кавычки.

Все команды принимают **однозначный начальный префикс** из общего registry:
`/sys python` = `/system python`, `/rel code` = `/reload code`.
`/s` и `/re` неоднозначны: ничего не выполняется, список вариантов показывается,
исходный ввод остаётся в редакторе. Точное имя всегда имеет приоритет.
`/help` строится из registry и показывает минимальные допустимые префиксы.

Основные команды:

```text
/help                     команды и клавиши
/new [name]               архивировать текущий диалог и начать новый
/clear                    архивировать и очистить текущую сессию
/archive [name]           сохранить снимок без очистки
/sessions                 список архивов
/open ID                  восстановить архив; допустим уникальный префикс ID
/system [РОЛЬ]            показать список ролей или выбрать одну роль
/system show [РОЛЬ]       показать текст активного или указанного промпта
/load "path with spaces" code
/reload code              перечитать файл; при ошибке старая копия остаётся
/files                    источники, размер, строки, изменения на диске
/unload code              удалить источник
/context                  подробный подсчёт текущего контекста
/status                   текущее состояние
/tokens                   расход входных и выходных токенов за запрос и сессию
/paths                    действующие служебные пути
/select                   просмотр и выделение последнего ответа
/copy [FIRST LAST]        копирование ответа, выделения или диапазона строк
/save [PATH]              экспорт последнего ответа
/code                     список fenced code blocks последнего ответа
/code script.py           экспорт единственного блока
/code 2 playbook.yml      экспорт выбранного блока
/search TEXT              поиск без учёта регистра; повтор — следующий результат
/retry                    повтор последнего user request с текущими настройками
/stop                     остановка с сохранением partial answer
/reasoning [full|summary] показ текста рассуждений или живого счётчика
/quit                     сохранение и выход
```

`/save` и `/code N` без пути создают файл в exports. Существующий файл никогда не
перезаписывается: выберите другое имя. `/retry` сохраняет предыдущую попытку в
transcript, помечает её superseded и исключает из повторного API-контекста.

## Расход токенов

В верхней строке `IN` и `OUT` показывают суммарный расход входных и выходных
токенов текущей сессии. `/tokens` показывает также статистику последнего запроса
и количество ответов без статистики. Данные берутся из серверного `usage`:
`prompt_tokens` и `completion_tokens`. Входные токены включают весь отправленный
контекст каждого запроса, а не только новый текст пользователя.

Сумма включает предыдущие попытки `/retry`, остановленные и ошибочные ответы,
если сервер успел сообщить статистику. Повторные обновления `usage` заменяют
счётчик попытки, а не прибавляются к нему. `?` означает неизвестный расход;
`250+?` — известны 250 токенов, но статистика части ответов отсутствует.
При остановке потока итоговый `usage` может не поступить; оценка по длине текста
не подменяет расход сервера. Счётчики сохраняются вместе с диалогом, восстанавливаются
при запуске и открытии архива; `/new` и `/clear` начинают подсчёт с нуля.

## Источники и контекст

Загрузка файла сама по себе не отправляет его модели:

```text
/load test.py code
Проверь @code
Проверь только @code#L10-L30
```

Поддерживается и одна строка: `@code#L50`. Номера начинаются с 1, границы
проверяются. Источники читаются как UTF-8, бинарные и слишком большие файлы
отклоняются; лимит задаёт `MAX_SOURCE_FILE_BYTES`.

Только явно указанные источники добавляются к текущему API-запросу с путём и
номерами строк. Снимок развёрнутого запроса сохраняется в metadata для истории,
но в последующие API-запросы источники автоматически не добавляются.
Для повторного анализа используйте `@alias` снова.

Размер контекста определяется по metadata выбранной модели или llama.cpp `/props`.
Если модель выбрана, TUI запрашивает `/props?model=<URL-кодированное имя>`:
это работает и в режиме одной модели, и в
[router с несколькими моделями](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md#routing-requests).
Используется `default_generation_settings.n_ctx` — рабочий контекст на один слот,
а не обучающий `n_ctx_train` из GGUF. После `/model NAME` лимит определяется заново.
В router запрос метаданных может автоматически загрузить выбранную модель,
согласно настройкам llama-server. Ответ `/props` ожидается до `HTTP_TIMEOUT`
(по умолчанию 60 секунд), соединение устанавливается с тайм-аутом `CONNECT_TIMEOUT`
(5 секунд). Ожидание выполняется в сетевом потоке и отменяется через Esc.
Имя выбранной модели также передаётся в `/apply-template` и `/tokenize`, чтобы
маршрутизатор использовал её шаблон и токенизатор при подсчёте контекста.
Явное числовое `context_size` в `BACKENDS` имеет приоритет над обнаруженным
значением. Runtime override сохраняется в сессии:

```text
/context max 131072
/context reserve 8192
/context auto
```

`/context auto` снимает runtime override и возвращает backend configuration.
При неизвестном лимите показывается `?` и предупреждение; автоматический trimming
отключён. Выдуманного максимума нет.

llama.cpp использует `/apply-template` + `/tokenize`, vLLM — chat-aware `/tokenize`.
Если endpoint отсутствует или выдаёт некорректные данные, используется явно
обозначенная оценка `~`. Во время ввода и до получения точного подсчёта статус
также приблизительный. По F5 worker считает фактический текст редактора;
`/context` считает историю без текста самой команды. Компоненты breakdown
приблизительные, поскольку overhead шаблона не складывается независимо.

Из бюджета вычитается `response_token_reserve`; при явном `max_tokens` резерв
не меньше этого значения. При переполнении удаляются старейшие turns только из
API-контекста. Полный transcript остаётся доступным. System prompt, текущий запрос
и его источники не удаляются; если они не помещаются, запрос отклоняется с
описанием бюджета и предложением диапазона строк.

Резерв не навязывает серверу лимит генерации: в режиме SERVER сервер сам управляет
длиной ответа. Для явного ограничения используйте `/sampling max_tokens N`.

## Sampling и thinking

По умолчанию `SERVER`: optional sampling parameters не отправляются, используются
настройки сервера. Override действует только для заданных параметров:

```text
/sampling
/sampling temp 0.6
/sampling top_p 0.95
/sampling top_k 20
/sampling min_p 0
/sampling presence_penalty 1.5
/sampling max_tokens 8192
/sampling server
/sampling reset
```

`repeat_penalty` преобразуется адаптером vLLM в `repetition_penalty`.
Неизвестные параметры, NaN и недопустимые значения отклоняются.

`/thinking auto` не меняет defaults модели. `/thinking on` и `/thinking off`
отправляют `chat_template_kwargs.enable_thinking`, если для backend выставлено
`thinking_supported=True`. Включайте этот флаг только после проверки, что
**текущая модель и её шаблон** поддерживают переключение: не все reasoning-модели
позволяют отключать thinking. Без флага запрос переключения отклоняется с
сообщением. Отдельные reasoning deltas отображаются и сохраняются в metadata;
`/save` экспортирует текст итогового ответа.

Отдельно от настроек модели работает **показ рассуждений**:

```text
/reasoning full
/reasoning summary
```

F6 или Ctrl+D переключают эти режимы без остановки генерации. `full` показывает
текст, `summary` — только `Thinking`, анимированный индикатор, число полученных
символов рассуждений и прошедшее время. После ответа остаётся отметка количества
скрытых символов. Нижняя строка прогресса обновляется и тогда, когда новые данные
пока не приходят: счётчик отражает только реально полученные символы.
При переключении во время генерации отображается текущий ответ.
Над редактором постоянно показан текущий режим: `F6 мысли: счётчик` в скрытом
режиме и `F6 мысли: текст` в полном. Команда `/reasoning summary` явно включает
скрытый режим, `/reasoning full` возвращает полный текст.

Поддерживаются отдельные поля reasoning в API и ведущий блок `<think>…</think>`
в потоке текста, включая теги, разбитые между chunks. Рассуждения сохраняются в
metadata даже в скрытом режиме. Выбор режима сохраняется в сессии; при запуске
его можно задать через `--reasoning-view summary`. Начальное значение задаёт
`DEFAULT_REASONING_VIEW` в начале файла. `/thinking` меняет параметры модели,
а `/reasoning` меняет только отображение.

System prompts находятся в словаре `SYSTEM_PROMPTS`: general, architect, security,
python, bash, linux, ansible, devops, sre, network, database, code-review,
troubleshooter, log-analyzer и performance. Смена роли сохраняет диалог.

Выберите одну основную роль. Дополнительные требования укажите в тексте задачи:

```text
/system ansible
Проверь эту роль Ansible, включая безопасность: права доступа и хранение секретов.
```

Промпты нескольких ролей не объединяются. Роль сохраняется в сессии и архивах
и учитывается при подсчёте контекста. Старые сессии с объединёнными ролями
восстанавливаются с первой ролью; диалог сохраняется, изменение отмечается в журнале.

Текст промпта можно посмотреть, не меняя выбранные роли:

```text
/system show                 полный активный промпт
/system show security        промпт отдельной роли
```

Просмотр доступен во время генерации и не останавливает её. Текст показывается
в верхней панели; PgUp/PgDn прокручивают его. Tab дополняет каждую роль, включая
роль после `show`.

## Данные, логи и проверка

По умолчанию все служебные файлы находятся в `./llm-tui` относительно текущего
рабочего каталога. Графическая среда не требуется. XDG-переменные больше не
используются; старый параметр `--state-dir` заменён на `--log-dir`.

| Параметр | Что хранится и как выбирается путь |
|---|---|
| `--storage-dir ROOT` | Общий корень; по умолчанию `./llm-tui`. Альтернатива — переменная `LLM_TUI_HOME`. |
| `--data-dir DIR` | Сессии, архивы, экспорт и файл блокировки непосредственно в `DIR`; по умолчанию `<storage-dir>/data`. |
| `--log-dir DIR` | Журналы непосредственно в `DIR`; по умолчанию `<storage-dir>/logs`. |

Например, `python3.8 llm-tui.py --storage-dir /srv/llm-tui/alice` использует
`/srv/llm-tui/alice/data` и `/srv/llm-tui/alice/logs`. Для другого пользователя
укажите другой корень. `--paths` выводит фактические пути и сразу завершает программу.
`--help`, `/help` и подсказки клавиш переведены на русский; имена команд и значения
`auto`, `full`, `summary` и прочие ключевые слова сохранены.

По умолчанию:

```text
./llm-tui/data/current.json
./llm-tui/data/archive/*.json
./llm-tui/data/exports/*
./llm-tui/data/session.lock
./llm-tui/logs/llm-tui.log
```

Автоматический суффикс `sudo-UID` больше не добавляется. Отдельный корень для
каждого человека задаётся явно либо получается из разных рабочих каталогов.

Для одного выбранного корня:

```text
ROOT/data/current.json
ROOT/data/archive/
ROOT/data/exports/
ROOT/data/session.lock
ROOT/logs/llm-tui.log
```

Выбор корня: `--storage-dir` → переменная `LLM_TUI_HOME` → настройка `STORAGE_DIR`
в начале Python-файла (изначально `./llm-tui`). Явные `--data-dir` и
`--log-dir` переопределяют соответствующую часть этого выбора.

Старые сессии автоматически не перемещаются. Для их использования можно указать
`--data-dir` с прежним каталогом данных, а `--log-dir` — с прежним каталогом журналов.

Отдельного дискового кэша нет. Кэш подсчёта токенов и отображения хранится в памяти
процесса. В data также появляются временные файлы атомарного сохранения и, при
повреждении сессии, `corrupt-*.json`. Новые каталоги data/logs создаются с правами
0700. `session.lock` не позволяет двум экземплярам одновременно писать в один
current.json, даже если указан одинаковый явный путь. После выхода блокировка
освобождается; оставшийся lock-файл удалять не требуется.

Можно переопределить пути без изменения кода:

```bash
python3.8 llm-tui.py --data-dir ./data --log-dir ./logs
```

Сохраняются сообщения, источники, история ввода, черновик и настройки.
JSON записывается атомарно через temporary file, fsync и os.replace.
Повреждённый current.json сохраняется как `corrupt-*.json`, создаётся новая сессия.
Лог ротируется; `DEBUG=True` или `--debug` включает диагностику без API-ключей.

Проверки без backend:

```bash
python3.8 -m py_compile llm-tui.py
python3.8 llm-tui.py --self-test
```

API-адаптеры сверены с [документацией llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)
и [протоколом tokenize vLLM](https://github.com/vllm-project/vllm/blob/main/vllm/entrypoints/serve/tokenize/protocol.py).
Внешние endpoints могут различаться между версиями; optional tokenizer/metadata
отказывают с fallback, HTTP-ошибки появляются в transcript и логах.
